# ADR-008: v1.0.0 Release — Security, i18n, and Desktop Production Hardening

**Date:** 2026-05-04
**Status:** Accepted
**Impact:** Security, UX, i18n, Performance

## Context

v0.6.0 was audited and scored ~5/10 on production readiness. Key issues:
- Inverted semver (v1.0 released before v0.x)
- Guardrails with false positives blocking legitimate use
- No path traversal protection in code execution
- Auto-update with no signature verification
- Credentials in plaintext mykey.py
- Thread pool exhaustion in async frontends
- i18n infrastructure existed but was not used
- Desktop app was overlay-only, unusable for non-developers
- No onboarding wizard
- Raw Python exceptions shown to users

## Decision

1. Fix semver: reset to v1.0.0 (previous v1.0 should have been v0.1.0)
2. Remove factuality_check guardrail (censored honest responses)
3. Disable no_code_injection and no_pii_leak by default (ADR-007)
4. Add path traversal validation in code_run.py and file_ops.py
5. Make Ed25519 signature verification mandatory (fail-closed) for auto-update
6. Deprecate mykey.py with DeprecationWarning, add --migrate CLI to credential_store.py
7. Unify builtin tools in registry for proper specialist isolation
8. Migrate all frontend strings to i18n t() function (209 keys in en/fr/zh)
9. Replace asyncio.to_thread with asyncio.Queue bridge in chatapp_common.py
10. Connect circuit breaker state changes to EventBus → UI banner
11. Auto-activate ContextEngine with compaction at 70% context usage
12. Enable use_llm=True by default in orchestrator (LLM routing > keyword matching)
13. Change Qt default from overlay to normal window mode
14. Add GUI onboarding wizard (5 steps, stores API keys in keyring)
15. Add exception → user-friendly message mapper with suggested actions
16. Centralize colors in theme.py + external dark.qss
17. Add auto-update notification banner in ChatPanel
18. Make Qt UI HiDPI responsive (replace setFixedSize with QFontMetrics)
19. Raise test coverage target to 80% with per-module thresholds
20. Add 10 E2E tests with StubLLMClient
21. Add pre-commit hook for i18n string enforcement

## Consequences

- **Positive:** Security significantly hardened; UX usable for non-developers; i18n complete; performance bottleneck fixed
- **Negative:** Breaking change for users relying on mykey.py (deprecation path provided); use_llm=True by default increases token cost for routing (minimal: one short classification call per task)
- **Risk:** Some v1.0.0 features (onboarding wizard, error mapper) are new code that hasn't had extensive real-world testing yet
